# [TLSMemoryPool]

## 1. 개요 (Overview)
- 동적 할당을 미리 수행하여 원할 때 객체를 할당 받아 사용할 수 있는 풀이다. 또한 사용한 객체는 반환 이후 재사용 될 수 있다. 스레드마다 가지고 있는 TLS를 기반으로 멀티스레드 환경에서 락 경합을 줄인다.
- 동적 할당/해제 시 시간이 오래 걸리는 상황을 미리 할당하여 해결한다. 멀티스레드 환경에서는 디폴트 힙의 경합으로 인해 더욱 오래 걸릴 수 있는 상황을 스레드 별 힙을 가지고 할당하여 경합을 없앤다.
- STL을 이용하여 메모리를 저장할 수 있지만, STL의 노드 생성 시 할당이 이루어지기 때문에 결국 달라지는 것이 없다. 따라서 내부의 데이터만 재활용하는 것이 아닌 노드를 재활용하기 위해 침습성 리스트 방식을 이용한다.
- 빠른 메모리 할당 및 메모리의 재사용으로 향상된 성능을 제공한다

## 2. 왜 필요한가? (Motivation)
- new/delete 방식의 경우 할당/해제마다 적지 않은 오버헤드가 발생한다. 따라서 나온 것이 메모리 풀이며, 기존의 메모리 풀은 멀티스레드 환경에서 경합이 발생하여 속도가 느려진다는 단점이 존재한다.
- STL을 이용한다면 STL 내부의 노드 생성을 위해 할당을 받기 때문에 동일한 문제가 발생한다.
- 추가적으로 락프리 알고리즘을 공부하던 중 new/delete을 이용하여 락프리 알고리즘의 노드를 할당 및 해제 시 이미 해제된 노드에 접근하여 접근 위반 에러가 발생하는 경우가 존재하였다. 이를 위해 노드의 해제를 하지 않는 방법을 채택하여 메모리 풀이 필요하게 되었다.
- 더욱 빠른 할당과 메모리의 재사용을 기대할 수 있다. 멀티스레드 환경에서 자신의 로컬 힙을 이용하여 실제 할당 시 힙의 경합을 줄였으며, 로컬 풀을 이용하여 동기화를 제거하여 더욱 빠른 성능을 기대할 수 있다.

## 3. 핵심 개념 (Core Concepts)
- 할당 받은 메모리는 로컬 풀에서 동기화 없이 작동한다. 일정 개수 이상의 메모리가 존재한다면 다른 스레드가 노드를 가져갈 수 있도록 락을 걸고 분배용 풀에 삽입한다. 분배용 풀은 스레드마다 가지고 있으며, 하나의 풀이 된다면 병목 지점이 될 수 있을 것이다. 로컬 풀에 노드가 존재하지 않는다면 분배용 풀을 먼저 확인한 후 스레드 별 로컬 힙을 이용하여 메모리를 할당한다. 
- 침습성 리스트(노드 내부에 원하는 객체가 존재하며, 해당 객체의 포인터를 반환한다. 해제 시 노드 포인터를 계산하여 저장한다), 노드 리스트(노드는 자신의 다음 노드의 포인터를 들고 있다)
- 작동 방식 : 내부 그림으로 대체

## 4. 구현 상세 (Implementation Details)
- 클래스 구조
  - 책임 : 지정한 타입의 메모리의 할당 및 보관, 남는 메모리의 공유
  - 상태 : instance(동일 타입 객체 생성 불가를 위한 싱글톤 객체), leftStack(분배용 스택, 남는 노드를 삽입), _curNode(로컬 풀의 top), _leftNode(일정 개수 이상이 로컬 풀에 들어갔을 때 남는 노드를 넣음, 일정 개수 이상 쌓이면 분배용 스택에 삽입), stackIdx(스레드 별 자신의 인덱스), _allocUnit(일정 개수의 기준이 되는 변수)
  - 동작 : Alloc()을 이용하여 원하는 객체의 포인터를 받는다. 사용 이후 Free(T*)를 이용하여 반환한다.
- 주요 메서드
  - Init() : 스레드 로컬 데이터 초기화
  - Alloc(), Free(T*) : 할당 및 해제
  - AllocNewNode() : 분배용 큐에도 존재하지 않을 때 로컬 힙을 이용하여 할당
  - GetTotalSize() : 동적 할당한 모든 메모리의 개수
  - GetUseSize() : 로컬 풀에 가지고 있는 모든 메모리의 개수
- 내부 메커니즘 : 그림으로 대체

## 5. 사용 예시 (Usage Examples)
- 기본 사용법
  ```
  CObjectPool<StackNode> pool;
  StackNode* node = pool.Alloc();

  ...

  pool.Free(node);
  ```

## 6. 트레이드오프 (Trade-offs)
- 장점 : 할당 및 해제 속도가 빠르다. 
- 단점 : 단일 풀 방식 대비 메모리의 사용량이 더 높다.
- 적합한 사용 케이스 : 자료구조 노드 풀
