# [멀티스레드 기반 로그인 서버]

## 1. 개요 (Overview)
- 한 문장 요약 : 자체 제작 라이브러리 기반 멀티스레드 로그인 서버
- 주요 기능 : Redis 기반 세션 키 저장, MySQL 기반 유저 정보 조회
- 핵심 기술 스택 : C++ 17, Redis, MySQL
- [서버 구조 및 프로토콜](./Architecture.md)

## 2. 성능 목표 (Performance Goals)
   ### 2.1 타겟 지표 (부하 테스트, 10k 접속)
   |지표|기준치|달성치|
   |:---:|:---:|:---:|
   |레이턴시|<100ms|72ms|
   |처리량|3000TPS|7900TPS|
   |CPU 사용률|<10%|21%|
   |메모리|<500MB|320MB|

   ### 2.2 목표 설정 근거
   - 레이턴시는 인간이 즉시 반응한다고 느끼는 속도의 마지노선인 100ms로 설정
   - MMORPG 기준 10,000명의 동시 접속을 기준으로 초당 1,000번의 로그인 처리면 충분하다고 판단
   - CPU 사용률의 경우 다른 컨텐츠 서버 고려 10%만 사용을 고려
   - 네트워크 라이브러리 기준 10,000명의 세션 동시 접속 허용 시 약 300MB의 메모리 사용, 넉넉하게 500MB로 설정

## 3. 전체 시스템 성능(Overall Performance)
   ### 3.0 시나리오 (Scenario)
   - 2,500명 단위로 증가 시키며, 지속적인 로그인 시도

   ### 3.1 처리량 (Throughput)
   | 동시 접속  | 패킷 처리량     | TPS(Send) |
   |:---:|:---:|:---:|
   | 2,500     | 7k pps       | 3.5k       |
   | 5,000     | 10.2k pps       | 5.1k       |
   | 7,500     | 15k pps      | 7.5k      |
   | 10,000    | 15.8k pps      | 7.9k      |
   
   ### 3.2 레이턴시 (Latency)
   | 동시 접속 | 평균 |
   |:---:|:---:|
   | 2,500   | 72ms  |
   | 5,000   | 72ms  |
   | 7,500   | 72ms  |
   | 10,000  | 72ms  |
   
   ### 3.3 리소스 사용량
   | 동시 접속 | CPU (%) | 메모리 (MB) |
   |:---:|:---:|:---:|
   | 2,500    | 11      | 305        |
   | 5,000    | 17      | 308        |
   | 7,500    | 20      | 311        |
   | 10,000   | 21      | 316        |

   ### 3.4 특이사항
   - 7,500명에서 10,000명으로 넘어갈 때 성능의 샹상 폭시 선형적이지 않다.
   - 이는 로그인 서버의 성능상 한계까지 스레드를 모두 사용 중이라는 뜻이다. 현재 로그인 서버의 스레드는 50개(Concurrent 15개)로 스레드의 개수를 더 늘린다면 DB 접근으로 블락 상태로 들어가는 스레드가 생길 때 깨울 수 있는 스레드가 더 많아지면서 더 많은 처리를 할 수 있을 것이다.
   - 레이턴시는 DB에 접근하고 로그인 완료 패킷을 날리는 시간이 전부인데, 아직 수용할 수 있는 인원이 더 남아서 모든 결과가 동일하게 나온 것으로 보인다. 서버에서 스레드를 대기하는 인원이 많아지게 된다면 레이턴시는 자연스럽게 증가할 것이다. 그러나 초당 약 8k의 로그인을 처리도 무난하게 해내는 것을 보면 실제 환경에서도 무리 없이 작동할 것으로 보인다.
   - CPU 사용률에 대해서 목표로 한 10%의 CPU 사용률을 달성하기 위해서는 스레드의 개수를 줄이면 될 것이다. 그러나 처리량도 자연스럽게 내려가게 될 것이다.
